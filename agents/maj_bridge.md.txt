Module “CRM / Opportunités” (Lead → Brief → Contrat) 1.1 Écran : Pipeline des opportunités But Visualiser et gérer le flux de demandes clients depuis le premier contact jusqu’à la signature / go campagne, comme dans un pipeline Odoo CRM. Vue Type : Kanban par colonnes. Colonnes (stades) : Nouveau lead Brief en cours Proposition envoyée Gagné Perdu Carte “Opportunité” (Kanban) Champs affichés sur la carte : nom\_opportunité (string, obligatoire) client (ref Client, obligatoire) montant\_estimé (number, devise) segment (enum : Telco / Money / Business / Maxit / Autre) prochaine\_action (string courte ou icône + date) probabilité (0–100%, calculée ou saisie) date\_clôture\_estimée (date) Détail d’une opportunité (vue fiche) Champs principaux (section “Informations générales”) : nom\_opportunité (string, required) client (ref Client) contact\_principal (ref Contact) segment (enum) type\_demande (enum : Nouvelle campagne / Dispositif digital / Projet plateforme / Retainer annuel / Autre) montant\_estimé (number) monnaie (enum, par défaut FCFA) probabilité (0–100%, défault 20) stade (enum lié au pipeline) date\_création (datetime, auto) date\_clôture\_estimée (date) responsable\_agence (ref Utilisateur BRIDGE) source (enum : email, WhatsApp, réunion, inbound site, referral…) Section “Contexte & notes” : description\_courte (text) notes\_internes (text, visible agence seulement) Section “Lien avec BRIDGE” : brief\_lie (ref Brief, optionnel, 0..1) projet\_campagne\_lie (ref Projet campagne, optionnel, 0..1) Actions Changer de colonne (drag & drop) → met à jour stade. Bouton Créer un brief : ouvre un formulaire de Brief pré-rempli depuis les champs de l’opportunité, remplit brief\_lie dans l’opportunité. Bouton Convertir en projet (uniquement si stade = Gagné et brief\_lie validé) : crée un Projet de campagne (module Projets) et renseigne projet\_campagne\_lie. 2. Module “Briefs” (Lead → Brief → Contrat, plus liaison avec Projets) 2.1 Écran : Liste des briefs Vue Type : table + filtres. Filtres : statut (Brouillon / En révision / Validé client / Annulé) segment, client, responsable\_agence, période (date création / deadline). Colonnes : ID (BR01, BR02…) Titre (titre\_brief) Client Segment Responsable agence Statut Deadline Opportunité liée (nom\_opportunité) Projet campagne lié (nom\_projet) 2.2 Écran : Fiche brief (création / édition) Champs Section “Identification” id\_brief (string, généré) client (ref Client, required) segment (enum) titre\_brief (string, required) type\_campagne (enum : Always-on / One-shot / Lancement / Event / Plateforme / Autre) responsable\_agence (ref Utilisateur, CDP) statut (enum : Brouillon / Soumis client / En révision / Validé client / Annulé) Section “Contexte & objectifs” contexte (long text) problématique (long text) objectifs\_business (text) objectifs\_digitaux (text – ex : reach, engagement, conversions) KPI\_principaux (text, liste) Section “Cible & message” cible\_primaire (text) cible\_secondaire (text) insights\_clés (text) proposition\_valeur (text) tone\_of\_voice (text / tags) Section “Livrables & périmètre” plateformes\_ciblées (multiselect : Facebook, Instagram, TikTok, LinkedIn, X, WhatsApp, site…) types\_contenus (multiselect : post, story, vidéo, carrousel, display, article, landing page…) besoin\_influence (bool + précisions) besoin\_production (tournage, event, animation digitale…) Section “Calendrier & budget” date\_début\_souhaitée (date) date\_fin\_souhaitée (date) budget\_estime\_total (number) répartition\_budget (table : catégorie / montant : média, influence, production, animations…) Section “Lien pipeline / projet” opportunité\_liee (ref Opportunité) projet\_campagne\_lie (ref Projet – rempli à la validation du brief) Actions Soumettre au client (côté agence) → statut = Soumis client, notifie le client. Valider / Demander modifications (côté client) → change statut, garde un historique. Créer projet de campagne (si statut = Validé client) → crée un Projet + tickets gabarits (cf. module Projets). 3. Module “Projets & Tickets” (Planning → Production → Publication) 3.1 Écran : Liste des projets (campagnes & plateformes) Champs projet id\_projet (P01…) nom\_projet (string, ex : “Ramadan 2026 OM”) client (ref) segment (enum) type\_projet (Campagne / Always-on / Plateforme / Autre) responsable\_projet (ref CDP) statut (enum : En préparation / En cours / En pause / Terminé / Annulé) date\_debut (date) date\_fin (date) progression (%) calculée (en % de tickets terminés) budget\_total (number) budget\_consommé (number, agrégé du module Finance) Vue : Kanban par statut ou segment, ou liste avec filtres. 3.2 Écran : Fiche projet Sections : En-tête nom\_projet, client, segment, statut, responsable\_projet, progression. Onglet “Backlog & tickets” Vue table ou Kanban : Champs ticket (déjà proches de tes B040… dans le prototype) : id\_ticket (B040…) titre\_ticket (string) type\_ticket (enum : contenu organique / paid / asset influence / landing / email / autre) plateforme (enum) segment assignee (ref créatif / CM / autre) priorité (enum : Critique / Urgente / Normale / Basse) statut (Backlog / À faire / En production / En validation interne / À valider client / Validé / Publié / Annulé) progression (%) deadline (date) budget\_ticket (number) blocks\_calendar (bool, comme dans ton prototype) liés\_au\_calendrier (ref entrée calendrier, optionnel) Détail ticket : description (text) checklist (booleans : visuel, copie, CTA, sponso\_validé) fichiers (liste pièces jointes) commentaires (thread discussions) Onglet “Calendrier” Vue calendrier filtré sur ce projet (reuse du module Calendrier, cf. plus bas). Onglet “Budget & temps” Rappel budget\_total, consommé, reste, agrégé depuis les entrées de finance liées. Onglet “Docs & réunions” Lien vers documents partagés (type Nextcloud), résumés de réunions, liens de visios… 4. Module “Traffic IA” (Planning → Production → Publication) 4.1 Écran : File prioritaire (vue cockpit) Vue Liste verticalement des tickets triés par score (comme dans ton IA Traffic). Champs visibles : id\_ticket, titre\_ticket assignee projet / campagne priorité (badge couleur) deadline score\_IA (calculé) status progression blocks\_calendar (icône) Actions : Réassigner (menu déroulant des créatifs / CM) Passer en validation (change statut → En validation interne) Marquer livré (statut = Publié ou Livré) Widgets / métriques : Charge créative par personne (% et couleurs). Nombre de tickets critiques avant vendredi 17h. 5. Module “Calendrier des contenus” (Planning → Prod → Publication) 5.1 Écran : Calendrier hebdomadaire / multi-plateformes Vue Filtre semaine (S15, S16…) Filtre plateforme (All / Facebook / IG / TikTok…) Filtre segment Liste (ou grid) des entrées : Champs : id\_calendrier (généré ou composite jour+plateforme+projet) jour (string, ex : “Lun 07/04”) plateforme (enum) contenu (string : titre court) statut (enum : Brouillon / Pending / Production / Validé / Réservé / Rejeté) CM\_responsable (ref utilisateur) sponsoring\_montant (number) week (S15, S16…) checklist.visuel (bool) checklist.copie (bool) checklist.CTA (bool ou cta\_testé) checklist.sponso (bool) ticket\_lie (ref ticket) lien\_post (URL, optionnel) heure\_pub (time, optionnel) Sur chaque carte / ligne : Badges readiness : 4 pictos pour chaque check (vert / gris). Statut global (ex. “Ready 3/4”). Actions Créer une entrée (depuis projet / ticket ou direct). Approuver / Demander modifications (si rôle client ou accès validation). Marquer comme publié (ajoute lien\_post, heure\_pub). 6. Module “Validation client” (Planning → Publication, Lead → Brief) 6.1 Écran : File de validation Vue Liste des éléments à valider (briefs, contenus, axes créa, budgets). Champs : type\_objet (Brief / Contenu / Axe créatif / Budget) id\_objet (BRxx / B0xx / autre) titre client segment projet statut\_validation (En attente / Approuvé / Rejeté / À revoir) deadline\_validation propriétaire\_agence (CDP / créatif) Détail validation Aperçu du contenu (image / texte / embed). Section Commentaires client (thread). Section Réponse agence (thread). Actions (côté client) : Approuver Rejeter (avec commentaire obligatoire) Demander ajustement mineur (statut intermédiaire) Actions (côté agence) : Soumettre nouvelle version Archiver après validation finale. 7. Module “Reporting & Insights” (Reporting → Reco → Décisions) 7.1 Écran : Liste des rapports mensuels Champs : id\_report (RPT-2026-03-TELCO, etc.) client segment période (mois/année) statut (En préparation / Partagé / Validé / Archivé) analyste (ref utilisateur) date\_dernière\_mise\_à\_jour 7.2 Écran : Fiche report Sections : Header période, client, segment, analyste, statut. Bloc KPIs consolidés (table ou cartes) pour chaque plateforme : followers, reach, engagement, posts, top\_format, growth (comme dans ton prototype). pour chaque campagne active : nom\_campagne, reach, engagement, conversions, verdict (Maintenir / Ajuster / Stopper), insights\_clés. Bloc Recommandations Table recommandations (tu as déjà une structure) : id\_reco titre description impact\_estimé (text, ex : “Engagement +35%”) priorité (Haute / Moyenne / Basse) statut (Proposée / Validée / Refusée / En cours / Clôturée) owner\_action (Agence / Client) date\_décision Bloc Actions & décisions “Log des décisions” : date, décideur, recommandation\_assoc, commentaire, statut\_final. Actions : Marquer le report comme partagé (notifie les parties). Ajouter recommandation / Mettre à jour statut (pour le suivi des décisions). 8. Module “Finance” (Budget → Devis → Facturation) 8.1 Écran : Dashboard budget annuel Champs consolidés (tu les as déjà) : année budget\_total\_HT dépensé\_total\_HT taux\_consommation (%) commission TVA total\_TTC Section “Par catégorie” (table) : catégorie (Achats media / Influence / Animations & prod / ...) budget dépensé solde taux\_consommation couleur Section “Timeline mensuelle” (barres) : pour chaque catégorie, dépenses par mois (Jan–Dec). 8.2 Écran : Devis / engagements Table “Devis / engagements” : id\_devis client projet / campagne description montant\_HT catégorie\_budget (media, influence, prod…) statut (Brouillon / Soumis client / Approuvé / Rejeté) date Actions : Soumettre au client (change statut + notifie). Approuver / Rejeter (client). Relation : chaque devis validé augmente dépensé de la catégorie correspondante, ou vient alimenter la capacité à facturer (selon ton choix de design). 8.3 Écran : Factures Table : id\_facture client projet montant\_HT TVA montant\_TTC date\_facture date\_paiement (optionnel) statut (Brouillon / Envoyée / Payée / En retard) Lien : chaque facture est liée à un ou plusieurs devis ou engagements. 9. Module “Documents & Collaboration” (Docs & Gouvernance) 9.1 Écran : Documents projet Vue par projet : Champs document : id\_document nom\_fichier type (brief / short deck / guideline / créa / contrat / autre) version projet / campagne auteur date\_upload tags Fonctions (pattern Nextcloud) : Commentaires sur fichier (thread). Lier un document à une tâche / ticket (ex : “déclencher une tâche de mise à jour quand un doc est modifié”). Demander “Approvisionnement / signature” (workflow simple d’approbation type Nextcloud Flow). 10. Module “Tâches transverses & Automations” 10.1 Écran : Tâches transverses Champs : id\_tâche titre type (Action liée à doc / Reco / Finance / Autre) liée\_à (ref objet : document, reco, devis, etc.) assignee priorité statut (À faire / En cours / Terminé / Annulé) deadline 10.2 Automations simples (à implémenter plus tard) Règles (inspirées de Nextcloud Flow) : Quand brief.statut passe à Validé client → créer un projet de campagne + tâches gabarits. Quand contenu.statut passe à Approuvé → marquer la tâche liée comme Terminé. Quand recommandation.statut passe à Validée → créer une ou plusieurs tâches d’implémentation. 11. Rôles / acteurs et droits à prévoir Pour tous ces écrans, prévois des permissions (RBAC) en fonction des profils BRIDGE : Admin Agence : accès à tout, y compris Finance & Admin. Chef de Projet : accès CRM, Briefs, Projets, Traffic, Calendrier, Validation interne, Reporting, partiel Finance. Community Manager : accès Projets, Tickets, Calendrier, Traffic, Validation (lecture) & Docs. Influence Manager : accès Projets, Tickets type influence, Influence, Finance (partie influence). Web Analyst : Reporting & Insights, Dashboard campagne, accès lecture aux projets et finance. Client Digital Lead / Marketing : accès lecture CRM, Briefs, Projets, Calendrier, Validation (actif), Reporting, vue synthèse Finance.
